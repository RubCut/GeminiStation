# Проверка BUG_REPORT.md

Статический разбор 42 пунктов отчёта относительно `main` на момент проверки. Это не результаты испытаний на станции. «Не подтверждено» означает, что описанная в отчёте причинная связь не следует из кода; это не гарантия отсутствия других проблем. Пункты с остаточным риском оставлены явно.

| № | Результат | Обоснование и оставшиеся ограничения |
|---|---|---|
| 1 | Не подтверждено; добавлена регрессия | Временная метка используется для `/api/led/preview/custom/...`; проверка SHA — только для `/led/*.gif`. Превью не проходит через эту проверку. На станции не проверено. |
| 2, 40 | Исправлено | `/api/config` больше не удаляет список ключей, отвергает `deleteKey: true` и неправильные типы; удаление конкретного ключа остаётся в `/api/keys`. Мёртвый параметр UI удалён. Старые клиенты с `deleteKey:true` получат ошибку. |
| 3 | Уточнено и усилено | `apply()` сразу изменяет данные в памяти, поэтому описанное старое чтение в том же процессе не следует из него. Запись на диск асинхронная: теперь удаление использует `commit()` и сообщает ошибку записи; кэш LED и личный детектор инвалидируются даже при ошибке. |
| 4 | Частично | Чтение списка устройств вынесено из блокировки, с повторной проверкой доступа перед командой. Сам сетевой запрос команды остаётся под блокировкой (до таймаута), чтобы отзыв разрешения не мог обогнать отправку. Полное устранение ожидания требует отдельного протокола отмены и не заявлено. |
| 5 | Исправлено другое реальное окно | Колбэки на главном потоке последовательно ставят таймер при обоих порядках, но прежний `onConnected` снимал watchdog до готовности микрофона и мог снять таймер речи. Теперь watchdog сохраняется до готовности, дедлайн речи не снимается. |
| 6 | Не исправлено | `captureStarted` консервативен намеренно: перезапуск после начала захвата теряет фразу и буфер даже без отправленного чанка. Надёжный перенос буфера и захвата между сессиями не реализован; при 429 после старта нужна повторная фраза. |
| 7 | Исправлено | Буфер сливается без удержания монитора; новые чанки сохраняют порядок в ограниченной очереди, конец ввода идёт после очереди. Есть конкурентный тест. Это не измерение на микрофоне устройства. |
| 8 | Исправлено | Нулевой результат записи повторяется с паузой и ограничением в 3 секунды; отрицательные коды остаются ошибками, отмена проверяется. Требует аппаратной проверки. |
| 9 | Не подтверждено | Закрытие и отправка проходят через один executor; `change` отменяет отложенное закрытие, а повторная отправка проверяет поколение и `connect()` восстанавливает соединение. Полностью исключить особенности прошивки без устройства нельзя. |
| 10 | Остаточный риск | При тишине callback означает только отправку, не подтверждённое воспроизведение. Ошибка после первой секунды попадёт в журнал, но может не попасть в уже закрытый диалог. Без надёжного ACK нельзя честно гарантировать результат; UX поздней ошибки требует отдельной доработки. |
| 11 | Частично исправлено | После неожиданного завершения записи предусмотрены максимум три попытки с паузой 3/6/12 с, затем сообщение об ошибке; после минуты стабильной записи лимит сбрасывается. Ошибка первоначальной инициализации не перезапускается автоматически. Нужна проверка на устройстве. |
| 12 | Остаточный риск | Ожидание освобождения микрофона ограничено 4 с. Убирать его без безопасной передачи владения нельзя: иначе два захвата могут конкурировать. При зависшем драйвере диалог не стартует; диагностика на реальном устройстве необходима. |
| 13 | Исправлено | Принимаются только числовые loopback-адреса, включая IPv6 и IPv4-mapped IPv6; имена не разрешаются через DNS. Добавлены тесты. |
| 14 | Ограничение безопасности | HTTP Host/Origin намеренно ограничены локальными адресами во избежание DNS rebinding. mDNS и HTTPS-прокси не поддерживаются; расширять allowlist без модели доверия небезопасно. |
| 15 | Задуманное ограничение | При уходе Activity останавливает микрофон и сетевой запрос и закрывает диалог, чтобы не слушать невидимо. Сохранение диалога через системные окна потребует отдельной безопасной модели возобновления. |
| 16 | Уточнено | `wakeResetMs` уже скрыт в интерфейсе и не подключён. Значение сохраняется для совместимости backup, но больше не вызывает лишний перезапуск детектора. Не заявляется как работающая настройка. |
| 17 | Не подтверждено | `release()` сначала устанавливает `activationPlaying=false`; оба цикла `VoicePlayer.play` проверяют этот флаг. Поведение заблокированного драйвера AudioTrack на устройстве отдельно не проверено. |
| 18 | Частично исправлено | `ACTION_UP` выполняется даже при исключении на DOWN; при исключении на UP делается повторная попытка. Гарантировать доставку, если Android отклоняет оба вызова, нельзя. |
| 19 | Исправлено | Цель ограничена минимумом и максимумом аудиопотока; минимальный шаг уже составлял 1. Поведение физического регулятора не проверено. |
| 20 | Усилено, риск остаётся | `executeWithConfig` запускает Python в отдельном потоке и сам не ждёт Python. Добавлен независимый watchdog процесса runner на 47 с; Binder/системные зависания и дочерние shell-процессы этим не гарантированно устраняются. |
| 21 | Не подтверждено | `IPluginResult` не `oneway`: синхронный Binder-callback возвращается после обработки. Процесс завершается после возврата, а `busy` живёт только в этом процессе. |
| 22 | Не подтверждено | Чистые GitHub Actions успешно собирают `pluginrunner`, включая [сборку после исправлений](https://github.com/RubCut/GeminiStation/actions/runs/42372971962). Предположение об отсутствии зависимости не воспроизведено. |
| 23 | Исправлено | Шрифт и встроенные GIF сначала читаются в байты; длина ответа берётся из массива, не из `available()`. |
| 24 | Усилено | NanoHTTPD уже запускается с idle-таймаутом сокета 5 с; добавлен лимит общей продолжительности загрузки записи 20 с между чтениями и обработка socket timeout. Один уже блокирующий read может добавить до таймаута сокета. |
| 25 | Не подтверждено | Ответ JSON создаётся через `newFixedLengthResponse`; gzip здесь не определяет chunking. Экспериментальный QR-вход всё равно требует проверки на устройстве. |
| 26 | Исправлено | Проверка длины выполняется до добавления лишнего символа; предыдущий код также отказывал строке длиннее лимита, но временно выделял ещё символ. |
| 27 | Не подтверждено | `request(limit + 1)` ограничен запрошенным размером (с гранулярностью буфера) и не читает бесконечный поток до EOF; сетевые клиенты имеют таймауты. |
| 28–29 | Не подтверждено | Сам отчёт отмечает копирование snapshot и пропуск кадра без новых признаков. Потоковая модель остаётся зависимой от корректности будущих изменений. |
| 30 | Не подтверждено | В Live уровень логируется раз в 2 с, а не на каждом 100-мс чанке. Без профилирования на станции утверждение о заметном jitter не доказано. |
| 31 | Не подтверждено | Проверка `>= 5` идёт до инкремента, значит пятая попытка разрешена, шестая заблокирована. |
| 32 | Не подтверждено | Валидация находится перед `try/finally`. После начала записи `finally` нужен и при частичной ошибке, чтобы детектор увидел частично изменённые настройки. |
| 33 | Заданный контракт | Маркер завершения учитывается только в конце; маркеры внутри текста удаляются без завершения. Это явно тестируется и является безопасным выбором при неоднозначном выводе. |
| 34 | Не подтверждено | `flow.answered()` переводит фазу в SPEAKING до вызова `speak()`, а не в `onPlaybackStarted`. Поэтому обычный провал TTS до звука не оставляет фазу THINKING. |
| 35 | Частично исправлено | Опрос отключён для фоновой вкладки и возобновляется при возвращении. Пока вкладка видима, полный снимок журнала всё ещё передаётся раз в 5 с. |
| 36 | Не подтверждено как пользовательский симптом | `address()` не вызывается в приложении; возможный выбор VPN-адреса остаётся проблемой, если метод будет использован в будущем. |
| 37 | Не подтверждено | `onStop` вызывает `fail`, который при совпадении поколения выполняет `release()` и снимает таймер. При явном `stop()` таймер снимается самим `release()`. |
| 38 | Не подтверждено | `WakeSensitivity.normalize` возвращает допустимое число, как признаёт отчёт. |
| 39 | Исправлено | На 401 перезагрузка инициируется не более одного раза на страницу до разбора JSON; не-JSON ответ получает понятную ошибку. Проверено UI-тестом. |
| 41 | Не подтверждено | Описана нестандартная последовательность событий без воспроизведения; намеренно не меняем обработку системной кнопки без устройства. |
| 42 | Не подтверждено как описано | Панель не опрашивает `/api/plugins` каждые 5 с. Синхронные чтения под общей блокировкой действительно могут задерживать другие вызовы, но масштаб не измерен; снятие проверок hash/разрешений без анализа небезопасно. |

Проверки: Node-тесты панели, хоста и UI плагинов, тесты обработки аудиобуфера, политики loopback, повтора wake и другие JVM-тесты в GitHub Actions. Персональные записи, токены и данные станции не использовались.
